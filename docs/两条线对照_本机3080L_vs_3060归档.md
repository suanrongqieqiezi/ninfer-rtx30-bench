# 两条 NInfer × Bonsai-27B 路线的对照

日期：2026-09-30 | 目的：厘清"本机 3080 Laptop 那条线"与"C 盘 Downloads 汇总那份（3060）"到底哪同哪不同

---

## 0. 一句话

**同主题、同结论方向、甚至速度数字都接近；但机器不是同一台，踩的坑几乎相反。**

- 共同点：都是 Ternary-Bonsai-2-27B + NInfer 在 **Ampere 消费卡（sm_86）** 上**自编译**跑通，都走 **DFlash2 K=7** 投机路线。
- 不同点：**一张 3080 Laptop 16G（本机 E:\AI），一张 3060 12G（另一台 D:\27b）**。两张卡的架构门、工具链、内存墙全不一样。

---

## 1. 硬证据：不是同一台机器

| 核查项 | 本机 | C 盘那份（3060）自称 |
|---|---|---|
| GPU | **RTX 3080 Laptop GPU**（nvidia-smi 现查） | RTX 3060 12G / 28 SM / ~360 GB/s |
| 项目路径 | `E:\AI\`（ninfer-3090-master、build-ninja、bench_lookup 全在） | `D:\27b\pkg1-fast-pq2`、`D:\build\infer86` |
| 该路径是否存在 | ✅ 存在 | ❌ **本机无 D 盘，`D:\27b`、`D:\build` 都不存在** |

→ C 盘那份的路径在本机复现不了，**它是另一台 3060 机器的成果**；workspace\3060归档 只是它的复制件（20 文件零差异）。

---

## 2. 逐维度对照

| 维度 | 本机（3080 Laptop 16G） | 3060 归档 |
|---|---|---|
| **卡** | 3080 Laptop，**30 SM**，16 GB | 3060，**28 SM**，12 GB |
| **代码线** | master 自编译（另有 franken/v0.11 一条支线） | master 自编译（cc86 引擎） |
| **工具链** | **CUDA 12.8 + VS2022（MSVC 14.44）** | **CUDA 13.3 + VS18（MSVC 14.51）** |
| **工具链坑的方向** | 编译器**太老**：`-std=c++20` 被静默降级成 C++17 → device.h 炸 100 错。换 VS2022 解决 | 编译器**太新**：CUDA 12.8 不认 MSVC 19.51（C1189 host_config）→ **换 CUDA 13.3** 解决 |
| **架构门拦在哪** | BF16 GDN gating **调度路由表**（按 3090 的 82 SM 设计，本机 30 SM 全不合法）→ 打补丁跳过非法路由 + 回退 MmaUnsplit | CMake **架构白名单**只编了 sm_89/sm_120 → 加 86；另加 `NINFER_SM_COUNT` 86→28 分支 |
| **FP8 墙** | 报告未列为主坑（master 线已含 sm_86 排除块） | **明确踩到**：sm_86 无 FP8 张量核，12 个 FP8-mma 单元 ptxas fatal → 排除 + `fp8_a8_stubs.cpp`（新增文件） |
| **12G 显存坑** | 无（16G 用默认 `--kv-capacity auto`） | **有**：dflash2 权重 9.10 GiB，`auto` 强制多留 1 GiB → 12G 卡**拒启**，必须改**显式容量** |
| **内存墙事故** | 无记录 | **有**：31.8 GB RAM 用 `-j 24` 编译 → 内核 BugCheck **死机**，降 `-j 6` |
| **最终 decode** | 普通 **~120**，重复密集 **~160**（+lookup-ngram） | 中位 **108.7**（DFlash2 K=7）；prefill 640 |
| **正确性** | MD5 位级一致（greedy 温度0） | 逐字节相同 + 金标准 3/3 |
| **额外做的** | **隐藏开关扫参**（lookup-ngram / mlp-a8-decode / prefill-cublas / kv-dtype k8v4）——这份 3060 归档没有 | 六份报告体系、技能包 ninfer-port-and-tune、测量夹具 |
| **时间** | 2026-09-27 | 2026-09-28（晚一天） |

## 3. 结论层面的异同

**同：**
- 官方预编译包对 sm_86 **架构门拒绝** → 只能自编译（两边都一样）。
- **DFlash2 是甜点，K=7 是硬上界**：DFlash2 一趟并行出 K 个草稿，K=5→7 每轮只涨约 2 ms；MTP 是每草稿 +5 ms 串行。
- decode 数字量级接近（本机 ~120 vs 3060 108.7），都远快于 llama.cpp 基线。

**不同（关键分歧）：**
- **"能不能自编译"在这两台机器上是两个不同难题**：本机卡在宿主编译器太老（C++20 降级），3060 卡在编译器太新 + FP8 缺失 + 架构白名单。**照抄任何一方的命令到另一方都会失败。**
- **`--kv-capacity` 的用法是反的**：3060 必须要显式值（12G），本机应当保留 `auto`（16G）。3060 报告自己也警告"别把这条抄到别的卡上"。
- **本机多测了一整块"隐藏无损开关"**，3060 归档没做这块（但对调优技能包有兴趣）。

---

## 4. 会不会是同一批人做的？

- 文件层面查不出署名（mtime 全是打包时间），**单看文件无法判定作者**。
- 但两边**共享同一套方法论**（同目录命名习惯、同样的"带宽折算目标线"口径、同样的 DFlash2/MTP 权衡叙述、技能包结构），像是同一思路在不同机器上的两次实施。
- 要坐实归属，得翻当时对话或别的痕迹——文件本身给不出。

---

## 5. 可复用的交集

如果要把两条线合成一份"RTX30系跑 NInfer Bonsai 通用手册"，互补的地方很明显：

- **3090/3080 桌面与笔记本**：用 auto kv-capacity + 隐藏开关扫参（本机线）
- **3060 12G**：用显式 kv-capacity + FP8 stub + 架构白名单补丁（3060 线）
- **共用**：DFlash2 K=7 + `--lm-head-draft`，自编译路径，金标准/逐字节正确性判据
