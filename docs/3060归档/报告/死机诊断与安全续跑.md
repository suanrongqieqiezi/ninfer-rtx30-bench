# 死机诊断与安全续跑（2026-09-28 07:54）

> 事件：自编 cc 8.6 引擎（路线 B）过程中，编译进程满核运行时**系统内核级崩溃（死机）**。
> 结论：**不是项目问题，是编译并行度打爆物理内存**。构建进度**未受损**，可安全续跑。

---

## 一、事件定性：内核级崩溃（BugCheck），非应用卡顿

Windows 事件日志（System 通道）取到的**直接证据**：

| 时间 | 来源 | 内容 |
|---|---|---|
| 07:53:32 | `volmgr` | **转储文件创建失败，因为在创建转储期间出错。BugCheckProgress = 0x00020004** |
| 07:53:40 | `EventLog` | **上一次系统的关闭是意外的**（Event ID **6008**） |
| 07:49 | （构建日志） | `build-k0.log` 停止推进于 `[300/316]` |

`Event ID 6008` = 意外关机；`volmgr + BugCheckProgress` = 内核触发了 BugCheck（蓝屏级）。
⇒ 这是**内核崩溃**，不是普通进程卡死。

## 二、根因：`-j 24` 并行 × 大内存 CUDA 单元 > 物理内存

| 项 | 实测值 |
|---|---|
| CPU | i7-13700 ｜ 16 物理核 / **24 逻辑核** |
| 物理内存 | **31.8 GB** |
| 原构建并行度 | **`-j 24`**（占满全部 24 逻辑核） |

模板密集的 CUDA 编译单元在 nvcc 的 `cudafe++ / cicc / ptxas` 阶段单进程峰值常达 **1.5–3 GB**。
`24 × ~2 GB ≈ 48 GB > 31.8 GB` → 换页风暴 + 磁盘 IO 打满 → 内核失稳 → BugCheck。
**这是典型的"编译并行度过高打爆内存"死机。**

## 五、安全续跑方案

**脚本：`D:\build\bld86-resume-j6.bat`**（纯 ASCII，已校验）

改动（相对上次 `-j 24` 的脚本）：
1. **`-j 24` → `-j 6`**：峰值内存压到 ~12–15 GB，远离 31.8 GB 天花板
2. 启动前 `del .ninja_lock`：清除死机残留锁

其余不变（CUDA 13.3 + 手动注入 Windows SDK 路径 + `-k 0` 遇错继续）。

**风险提示**：i7-13700 属 Intel 13 代（该代存在已知的高压/高温稳定性问题，Intel 已发微码修复）。
若在 `-j 6` 下**仍**崩溃，则指向硬件层，届时建议先更新 BIOS/微码再编。
